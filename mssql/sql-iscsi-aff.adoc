= Bereitstellung von SQL Server 2025 auf NetApp AFF mithilfe von iSCSI-LUNs
:allow-uri-read: 


[role="lead"]
Bereitstellung von SQL Server 2025 auf Windows Server 2025 mit Benutzerdatenbanken, Transaktionsprotokollen, TempDB und Protokollsicherungen auf iSCSI-LUNs auf einem NetApp AFF System. Dieses Verfahren umfasst die Konfiguration von iSCSI auf der ONTAP SVM, der Initiatorgruppe und der LUNs, des Windows iSCSI-Initiators, von MPIO und Datenträgern sowie die Installation von SQL Server.



[[scope]]
[[intro-scope]]
== Umfang

Dieses Verfahren stellt eine eigenständige SQL Server 2025 Instanz auf einem einzelnen Windows Server 2025 Host mit Benutzerdatenbanken, Transaktionsprotokollen, TempDB und Protokollsicherungen auf iSCSI-LUNs bereit. Dasselbe Storage-Design gilt für SQL Server Failoverclusterinstanzen (FCI) und Always On-Verfügbarkeitsgruppen, ihre clusterspezifische Konfiguration wird jedoch nicht behandelt. SQL Server Performance-Optimierung und Dimensionierung sind ebenfalls nicht Gegenstand dieses Verfahrens. Informationen zu den Vorteilen, Lösungskomponenten, Designprinzipien, einer Erklärung zur Funktionsweise von Multipathing und zur Datensicherung mit NetApp Console Backup and Recovery enthält link:sql-iscsi-aff-overview.html["Informationen zu SQL Server 2025 auf NetApp AFF mit iSCSI-LUNs"].



[[audience]]
[[intro-audience]]
== Publikum

Dieses Verfahren ist bestimmt für:

* *Storage-Administratoren*, die den ONTAP Cluster, die SVM, die iSCSI LIFs, die Initiatorgruppe und die LUNs konfigurieren.
* *Windows Administratoren*, die den Windows Server 2025 Host, den iSCSI-Initiator, MPIO und die Festplatten vorbereiten.
* *Datenbankadministratoren*, die SQL Server 2025 installieren und konfigurieren sowie Backup und Recovery einrichten.


Grundkenntnisse in der Administration von ONTAP System Manager, Windows Server und SQL Server werden vorausgesetzt.

Außerdem bleibt TempDB, das sich ständig ändert, aus den Snapshots Ihrer Benutzerdatenbanken ausgeschlossen.


TIP: Zur Lastverteilung lassen sich zusätzliche LUNs auf verschiedenen Controllern für zusätzliche sekundäre Datendateien (.ndf) nutzen.



[[prerequisites]]
== Voraussetzungen

Vor dem Start müssen die folgenden Voraussetzungen erfüllt sein:

.NetApp ONTAP
* Das AFF HA Paar ist installiert und der Cluster ist eingerichtet und betriebsbereit.
* Die iSCSI-Lizenz ist installiert. Sie ist in ONTAP One enthalten.
* Auf jedem Knoten existiert mindestens ein Datenaggregat (lokale Ebene).
* Die SVM ist vorhanden. In diesem Verfahren wird die bestehende SVM `{svm}` verwendet; iSCSI wird ihr hinzugefügt. Für die Erstellung einer dedizierten SVM für SAN ist das Menü:Cluster[Storage VMs > Add] zu verwenden, wobei *iSCSI* als Zugriffsprotokoll auszuwählen ist.
* Die Datennetzwerkports, die Broadcast-Domäne und (optional) die VLANs für die iSCSI LIFs sind konfiguriert. Im Labor verwendet die Broadcast-Domäne `MT9000` Jumbo Frames.
* Die Zeit wird zwischen dem Cluster, dem Host und Active Directory über NTP synchronisiert.


.Netzwerk
* Der SQL Server-Host verfügt über mindestens eine, vorzugsweise zwei dedizierte Netzwerkkarten für iSCSI im iSCSI-Subnetz oder VLAN.
* Die MTU ist durchgängig identisch (Host-Netzwerkkarte, Switches, ONTAP-Ports). Die Überprüfung der Jumbo-Frames erfolgt `ping -f -l 8972 <LIF-IP>` vom Host.


.Windows Server
* Windows Server 2025 (Desktop Experience) ist installiert, gepatcht und in die Domäne aufgenommen.
* Die NetApp Windows Host Utilities sind in einer für Windows Server 2025 unterstützten Version verfügbar (siehe den https://imt.netapp.com/matrix/["NetApp Interoperabilitätsmatrix Tool (IMT)"^]).
* Die Installationsmedien (ISO) für SQL Server 2025 und ein gültiger Produktschlüssel (oder eine kostenlose Edition) sind verfügbar.



NOTE: Im Gegensatz zu SMB-Dateifreigaben benötigen LUNs kein Domänenkonto für den SQL Server-Dienst. Die standardmäßigen virtuellen Konten (`NT Service\MSSQLSERVER`) können verwendet werden. Ein Domänenkonto oder ein gMSA wird jedoch weiterhin empfohlen, wenn die Instanz Netzwerkzugriff benötigt, beispielsweise für die Datensicherung auf einer Dateifreigabe oder für die Kerberos-Authentifizierung.

[[step-5-review-the-volume-and-lun-settings]]
[[volume-settings]]
== Schritt 5: Prüfung der Volume- und LUN-Einstellungen

Zu prüfen sind die Speicherplatz- und Snapshot-Einstellungen der vier Volumes. System Manager verwendet sinnvolle Standardeinstellungen; für SQL Server LUNs werden die folgenden Einstellungen empfohlen:

[cols="1,1,3"]
|===
| Einstellung | Wert | Grund 


| Speicherplatzgarantie (Volume) | `none` (dünn) | Kapazität wird nur verbraucht, wenn Daten geschrieben werden. 


| LUN Speicherplatzreservierung | `disabled` (dünn) | Thin LUN in einem Thin Volume. 


| LUN-Speicherplatzzuweisung | `enabled` | Aktiviert SCSI UNMAP, sodass der in NTFS freigegebene Speicherplatz an ONTAP zurückgegeben wird und der Host korrekt reagieren kann, wenn der Speicherplatz auf dem Volume knapp wird. 


| Snapshot-Richtlinie | `none` | Snapshots, die nicht applikationskonsistent sind, sind für SQL Server nutzlos. Backups werden von NetApp Console Backup and Recovery erstellt. 


| Snapshot-Reserve | `0` % | Der Snapshot-Speicherplatz wird stattdessen mit der automatischen Größenanpassung des Volume überwacht. 


| Automatische Größe | `grow`, maximal etwa 130 % der Volumengröße | Verhindert, dass die LUN offline geht, wenn Snapshots Speicherplatz belegen. 


| Speichereffizienz | aktiviert (standardmäßig auf AFF) | Inline-Deduplizierung, Komprimierung und Verdichtung haben keinen messbaren Einfluss auf die SQL Server Performance. 
|===
Die folgenden Befehle dienen zum Anwenden und Überprüfen der Einstellungen (dargestellt für `sql_iscsi_1_data`):

[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

.PowerShell

Die folgenden Befehle schalten die NetApp Datenträger online, initialisieren sie mit GPT, erstellen und formatieren auf jedem jeweils ein NTFS-Volume mit einer Zuordnungseinheitsgröße von 64K und erstellen die Ordner für SQL Server.

[source, powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----

CAUTION: Die Ausführung dieser Befehle ist nur dann vorgesehen, wenn diese LUNs die einzigen mit dem System verbundenen RAW-LUNs sind. Falls weitere RAW-LUNs mit dem System verbunden sind, müssen Sie die Ordner manuell erstellen und die Volumes formatieren.

[[step-9-verify-the-installation]]
[[post-install]]
== Schritt 9: Überprüfung der Installation

Erstellung einer Testdatenbank sowie Überprüfung, ob sich deren Daten- und Protokolldateien auf den NetApp LUNs befinden und ob die Storage-Pfade fehlerfrei sind.

.Schritte
. Öffnen des SQL Server Ports in der Windows-Firewall:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. Die Installation von SQL Server Management Studio (SSMS) erfolgt über den Link *Install SQL Server Management Tools* im Installation Center oder über die Microsoft-Website.
. Nach dem Start von SSMS erfolgt die Verbindung mit der Instanz (`{host}`) über Windows-Authentifizierung. Anschließend wird eine Testdatenbank erstellt; deren Daten- und Protokolldateien werden standardmäßig unter `E:\data` und `F:\log` angelegt.
. Überprüfung der Dateispeicherorte mit T-SQL:
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----
. Es ist zu überprüfen, ob die sofortige Dateiinitialisierung aktiviert ist:
+
[source, sql]
----
SELECT servicename, service_account, instant_file_initialization_enabled
FROM   sys.dm_server_services;
----
. Überprüfung des Storage vom Host und in ONTAP:
+
[source, powershell]
----
PS C:\> Get-Disk | Where-Object FriendlyName -like 'NETAPP*' | Format-Table Number,FriendlyName,Size,OperationalStatus,PartitionStyle
PS C:\> mpclaim -s -d
----
+
[source, console]
----
cluster::> lun show -vserver a50-sql -fields path,size,mapped,state
cluster::> vserver iscsi session show -vserver a50-sql
cluster::> qos statistics volume latency show -vserver a50-sql
----
. Optional: Test der Hochverfügbarkeit. Beim Ausführen einer Arbeitslast für die Testdatenbank erfolgen ein ONTAP Takeover und Giveback des Knotens, dem das Datenvolume (`storage failover takeover -ofnode <node>` / `storage failover giveback -ofnode <node>`) gehört. Die Arbeitslast pausiert einige Sekunden und wird fortgesetzt; die Datenbanken bleiben online.


.Was kommt als Nächstes
Der Schutz der Datenbanken erfolgt mit applikationskonsistenten Snapshot-Backups. Informationen zur Architektur, zum Backup-Workflow und zu den Vorteilen enthält link:sql-iscsi-aff-overview.html#console["Datensicherung mit NetApp Console Backup and Recovery"].



[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
[[cli-script]]
== Mit einem ONTAP CLI Skript lässt sich der Storage in einem Schritt konfigurieren

Das folgende Skript enthält die vollständige Storage-Konfiguration aus dieser Prozedur. Vor der Ausführung sind die Werte in spitzen Klammern zu ersetzen.

[source, console]
----
# --- iSCSI service and LIFs ----------------------------------------------
vserver add-protocols -vserver a50-sql -protocols iscsi
vserver iscsi create -vserver a50-sql -target-alias a50-sql

network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

# --- Initiator group -----------------------------------------------------
lun igroup create -vserver a50-sql -igroup sql-iscsi-1 -protocol iscsi -ostype windows -initiator iqn.1991-05.com.microsoft:sql-iscsi-1.sapcc.stl.netapp.com

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql_iscsi_1_data      -aggregate <aggr_node1> -size 560GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
volume create -vserver a50-sql -volume sql_iscsi_1_log       -aggregate <aggr_node2> -size 270GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 350GB
volume create -vserver a50-sql -volume sql_iscsi_1_tempdb    -aggregate <aggr_node2> -size 165GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 210GB
volume create -vserver a50-sql -volume sql_iscsi_1_logbackup -aggregate <aggr_node1> -size 325GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 420GB

# --- LUNs ----------------------------------------------------------------
lun create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -size 520GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -size 250GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -size 150GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -size 300GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled

# --- LUN mapping ---------------------------------------------------------
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -igroup sql-iscsi-1

# --- Verification ----------------------------------------------------------
vserver iscsi show -vserver a50-sql
network interface show -vserver a50-sql -data-protocol iscsi
lun show -vserver a50-sql -fields path,size,ostype,space-allocation,mapped,state
lun mapping show -vserver a50-sql
vserver iscsi session show -vserver a50-sql
----

TIP: Die Volumes werden auf die Aggregate beider Knoten verteilt, z. B. Daten- und Protokollsicherung auf Knoten 1 sowie Protokoll und TempDB auf Knoten 2. Dadurch werden die Ressourcen beider Controller genutzt.



[[use-a-powershell-script-to-configure-the-host-in-one-pass]]
[[ps-script]]
== Mit einem PowerShell Skript kann der Host in einem Durchgang konfiguriert werden

Das folgende Skript enthält die vollständige Hostkonfiguration aus diesem Verfahren. Die Ausführung erfolgt in einer mit Administratorrechten geöffneten PowerShell Sitzung; der MPIO-Teil erfordert einen Neustart.

[source, powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

NOTE: Die Ausführung erfolgt für jeden Teil separat. Teil 1 erfordert einen Neustart des Hosts, sodass die anderen Teile nach dem Neustart nicht fortgesetzt werden.


CAUTION: Die Befehle aus Teil 3 sollten nur ausgeführt werden, wenn diese LUNs die einzigen mit dem System verbundenen RAW LUNs sind. Falls weitere RAW LUNs mit dem System verbunden sind, müssen die Ordner manuell erstellt und die Volumes formatiert werden.
