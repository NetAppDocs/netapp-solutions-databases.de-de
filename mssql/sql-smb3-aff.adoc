[role="lead"]
Bereitstellung von SQL Server 2025 auf Windows Server 2025 mit Benutzerdatenbanken, Transaktionsprotokollen, TempDB und Backups auf kontinuierlich verfügbaren SMB 3-Freigaben auf einem NetApp AFF System. Dieses Verfahren umfasst die Konfiguration der ONTAP SVM, Volumes und Freigaben, die Installation von SQL Server und den Schutz der Datenbanken mit SnapCenter.



[[scope]]
[[intro-scope]]
== Umfang

Dieses Verfahren setzt eine eigenständige SQL Server 2025 Instanz auf einem einzelnen Windows Server 2025 Host ein, wobei sich Benutzerdatenbanken, Transaktionsprotokolle, TempDB und Backups auf SMB 3 Freigaben mit kontinuierlicher Verfügbarkeit (CA) befinden. Dasselbe Storage Design gilt für SQL Server Failoverclusterinstanzen (FCI) und Always On Verfügbarkeitsgruppen, ihre clusterspezifische Konfiguration wird jedoch nicht behandelt. SQL Server Performance Tuning und Dimensionierung fallen ebenfalls nicht in den Geltungsbereich. Eine Beschreibung der Vorteile, Lösungskomponenten, Designprinzipien und der Funktionsweise der kontinuierlichen Verfügbarkeit ist unter link:sql-smb3-aff-overview.html["Informationen zu SQL Server 2025 auf NetApp AFF mit kontinuierlicher Verfügbarkeit von SMB 3"] zu finden.



[[audience]]
[[intro-audience]]
== Publikum

Dieses Verfahren ist bestimmt für:

* *Storage-Administratoren*, die den ONTAP Cluster, die SVM, die Volumes und die SMB-Freigaben konfigurieren.
* *Windows und Active Directory Administratoren*, die den Windows Server 2025 Host, die Dienstkonten und das Netzwerk vorbereiten.
* *Datenbankadministratoren*, die SQL Server 2025 installieren und konfigurieren sowie Backup und Recovery einrichten.


Grundkenntnisse in der Administration von ONTAP System Manager, Windows Server und SQL Server werden vorausgesetzt.

Außerdem wird so verhindert, dass die sich ständig ändernde TempDB in die Snapshots Ihrer Benutzerdatenbanken aufgenommen wird.



[[prerequisites]]
== Voraussetzungen

Vor dem Start müssen die folgenden Voraussetzungen erfüllt sein:

.NetApp ONTAP
* Das AFF HA Paar ist installiert und der Cluster ist eingerichtet und betriebsbereit.
* Die CIFS (SMB)-Lizenz ist installiert. Sie ist in ONTAP One enthalten.
* Auf jedem Knoten existiert mindestens ein Datenaggregat (lokale Ebene).
* Die Uhrzeit des Clusters und von Active Directory wird über NTP synchronisiert. Die maximal zulässige Zeitabweichung für Kerberos beträgt 5 Minuten.
* Die Datennetzwerk-Ports, die Broadcast-Domäne und (optional) die VLANs für die SMB LIFs sind konfiguriert.


.Active Directory und DNS
* Eine Active Directory Domäne ist verfügbar, und die DNS-Server sind von den SVM-Daten-LIFs aus erreichbar.
* Sie verfügen über ein Konto mit der Berechtigung, Computerobjekte in der Ziel-OU für den CIFS-Server zu erstellen.
* Für SQL Server Database Engine und SQL Server Agent services ist ein dediziertes Domänenbenutzerkonto als Dienstkonto verfügbar.



IMPORTANT: SQL Server muss unter einem Domänenkonto ausgeführt werden, wenn sich seine Dateien auf einer SMB-Freigabe befinden. Integrierte virtuelle Konten (`NT SERVICE\MSSQLSERVER`) und lokale Konten können keinen Zugriff auf eine Remote-Dateifreigabe erhalten.

.Windows Server
* Windows Server 2025 (Desktop Experience) ist installiert, gepatcht und in die Domäne aufgenommen.
* Die Installationsmedien (ISO) für SQL Server 2025 und ein gültiger Produktschlüssel (oder eine kostenlose Edition) sind verfügbar.


.SMB Anforderungen und Einschränkungen für SQL Server auf ONTAP
* SMB 3.0 oder höher muss auf der SVM aktiviert sein.
* Alle Volumes, die CA-Freigaben hosten, müssen den *NTFS*-Sicherheitsstil verwenden und von Anfang an den NTFS-Stil gehabt haben.
* SMB Direct (RDMA) wird nicht unterstützt.
* ReFS wird nicht unterstützt. ONTAP (WAFL) stellt das Dateisystem für die Freigaben bereit.

Die folgenden Befehle erstellen dieselbe Konfiguration über die CLI. Die Platzhalterwerte in spitzen Klammern sind zu ersetzen.

[source, console]

cluster::> vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs

cluster::> vserver modify -vserver a50-sql -allowed-protocols cifs

cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>

. [[svm-smb-options,Konfigurieren der SMB-Serveroptionen]]Konfiguration der SMB-Serveroptionen. Voraussetzung ist, dass die für SQL Server erforderlichen SMB-Optionen auf der SVM aktiviert sind:
+
[source, console]
----
cluster::> set -privilege advanced
cluster::*> vserver cifs options show -vserver a50-sql -fields smb3-enabled,is-multichannel-enabled,is-large-mtu-enabled,copy-offload-enabled,shadowcopy-enabled
cluster::*> vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
cluster::*> set -privilege admin
----
+
[cols="1,3"]
|===
| Option | Zweck 


| `smb3-enabled` | Für dauerhaft verfügbare Freigaben ist SMB 3.x erforderlich. 


| `is-multichannel-enabled` | SMB multichannel verwendet mehrere TCP-Verbindungen und Netzwerkpfade für höheren Durchsatz und höhere Ausfallsicherheit. 


| `is-large-mtu-enabled` | Ermöglicht SMB-Lese- und Schreibvorgänge von bis zu 1 MB. 


| `copy-offload-enabled` | ODX-Kopierauslagerung; Kopien erfolgen innerhalb des Storage-Systems. 


| `shadowcopy-enabled` | Remote VSS für SMB-Freigaben. Erforderlich für Sicherungsanwendungen, die VSS für SMB-Freigaben verwenden. 
|===

[source, powershell]

Überprüfung und Anpassung der Speicherplatz- und Snapshot-Einstellungen jedes SQL Server Volumes.

.Beispiel anzeigen

.Beispiel anzeigen

image::sql25_smb_bp_026.png[Kontextmenü „Share“ mit „Edit“]

*** *Kontinuierliche Verfügbarkeit aktivieren*: *ausgewählt*
*** *Clients Zugriff auf das Snapshot-Verzeichnis erlauben*: deaktiviert
*** *Daten beim Zugriff auf diese Freigabe verschlüsseln*: deaktiviert (optional, abhängig von Ihren Sicherheitsanforderungen)

[[step-6-prepare-windows-server-2025]]
[[windows-prep]]
== Schritt 6: Windows Server 2025 vorbereiten

Die folgenden Schritte erfolgen auf dem SQL Server Host `{host}` als Domänenadministrator.

.Schritte
. Es ist zu überprüfen, ob der Server der Domäne beigetreten ist und ob der CIFS-Server aufgelöst werden kann (siehe <<svm-smb-options>>).
. Voraussetzung ist, dass das SQL Server-Dienstkonto in Active Directory vorhanden ist, z. B. `SAPCC\sql1admin`. Dabei wird entweder dasselbe Konto für die Datenbank-Engine und für SQL Server Agent verwendet, oder es wird für jede Komponente ein separates Konto verwendet. Unabhängig von der gewählten Option benötigt jedes Konto Zugriff auf alle vier Freigaben.
. Test des Zugriffs auf die Freigaben im Sicherheitskontext des Dienstkontos:
+
[source, powershell]
----
PS C:\> runas /user:SAPCC\sql1admin "cmd /c dir \\a50-sql\sql1_data && echo test > \\a50-sql\sql1_data\write-test.txt && del \\a50-sql\sql1_data\write-test.txt"
----
. Öffnen des SQL Server Ports in der Windows-Firewall:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. Überprüfung der SMB-Verbindung zur SVM. Der Dialekt muss 3.x sein und `ContinuouslyAvailable` muss `True`:
+
[source, powershell]
----
PS C:\> dir \\a50-sql\sql1_data | Out-Null
PS C:\> Get-SmbConnection -ServerName a50-sql | Format-Table ServerName,ShareName,Dialect,ContinuouslyAvailable,Encrypted,Signed
PS C:\> Get-SmbMultichannelConnection -ServerName a50-sql
----



NOTE: Windows Server 2025 erfordert standardmäßig die SMB-Signierung für alle ausgehenden SMB-Verbindungen. ONTAP unterstützt die SMB-Signierung und handelt sie automatisch aus. Die Signierung erhöht die CPU-Last auf beiden Seiten; dieser Aspekt sollte in den Performance-Tests berücksichtigt werden. Eine Deaktivierung der Signierung ohne vorherige Sicherheitsprüfung wird nicht empfohlen.

== Schritt 8: Installation überprüfen und eine Datenbank erstellen

Eine Testdatenbank wird mit SQL Server Management Studio (SSMS) erstellt, und es wird überprüft, ob sich ihre Daten- und Protokolldateien auf den SMB-Freigaben befinden. Optional kann in ONTAP bestätigt werden, dass die geöffneten Dateien Continuous Availability nutzen.

Die Pfade für Daten- und Protokolldateien sind standardmäßig auf  `+\\a50-sql\sql1_data+` und  `+\\a50-sql\sql1_log+` gesetzt.
+
.Beispiel anzeigen

====
. Die neue Datenbank erscheint im *Object Explorer*.
+
.Beispiel anzeigen
[%collapsible]
====

. Überprüfung der Dateispeicherorte mit T-SQL:
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----

[source, console]

cluster::> vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----
+
Alle SQL Server-Dateien müssen angezeigt werden `continuously-available: Yes`.





[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
== Mit einem ONTAP CLI Skript lässt sich der Storage in einem Schritt konfigurieren

Das folgende Skript enthält die vollständige Storage-Konfiguration aus dieser Prozedur. Vor der Ausführung sind die Werte in spitzen Klammern zu ersetzen.

[source, console]
----
# --- SVM -----------------------------------------------------------------
vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs
vserver modify -vserver a50-sql -allowed-protocols cifs

network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>
vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers

set -privilege advanced
vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
set -privilege admin

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql1_data    -aggregate <aggr_node1> -size 1TB   -security-style ntfs -junction-path /sql1_data    -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
volume create -vserver a50-sql -volume sql1_log     -aggregate <aggr_node2> -size 512GB -security-style ntfs -junction-path /sql1_log     -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_tempdb  -aggregate <aggr_node2> -size 500GB -security-style ntfs -junction-path /sql1_tempdb  -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 0 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_backups -aggregate <aggr_node1> -size 2000GB -security-style ntfs -junction-path /sql1_backups -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 2600GB

# --- CA shares -----------------------------------------------------------
vserver cifs share create -vserver a50-sql -share-name sql1_data    -path /sql1_data    -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_log     -path /sql1_log     -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_tempdb  -path /sql1_tempdb  -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_backups -path /sql1_backups -share-properties oplocks,browsable,changenotify,continuously-available

# --- Share permissions (repeat for each share) ----------------------------
vserver cifs share access-control create -vserver a50-sql -share sql1_data -user-or-group SAPCC\sql1admin -permission Full_Control
vserver cifs share access-control delete -vserver a50-sql -share sql1_data -user-or-group Everyone

# --- Verification ----------------------------------------------------------
vserver cifs show -vserver a50-sql
vserver cifs share show -vserver a50-sql -fields share-name,path,share-properties
vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----

TIP: Sinnvoll ist eine Verteilung der Volumes auf die Aggregate beider Knoten, zum Beispiel Daten und Backups auf Knoten 1 sowie Protokolle und TempDB auf Knoten 2. So lassen sich die Ressourcen beider Controller nutzen.
